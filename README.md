# Ассистент по практической фонетике английского (British RP)

Учебный MVP: RAG-ассистент по PDF-учебнику практической фонетики (British RP).  
Пользователь вводит слово и IPA-транскрипцию; система ищет релевантные фрагменты PDF и формирует ответ с источниками.

## Назначение и границы MVP

Ассистент помогает разобрать фонемы введённой транскрипции по материалам одного учебника.  
Это **не словарь** и **не генератор IPA**: транскрипцию всегда вводит пользователь.

### Правило ввода

Формат:

```text
слово | /IPA/
```

Примеры:

- `five | /faɪv/`
- `thought | /θɔːt/`

Приложение **не** подставляет IPA по слову и **не** исправляет транскрипцию.  
Пробелы внутри IPA отклоняются (например, `/f aɪ v/` — ошибка формата).

## База знаний

11 источников, 750 чанков:

- `sokolova_practical_phonetics.pdf` — учебник, 383 страницы, 727 чанков;
- 10 Markdown-файлов (`01_…`–`10_…` в `data/source/`) — глоссарии мест и способов артикуляции, таблица IPA, разборы фонем по страницам 36/44/47/79 и FAQ; всего 23 чанка.

Markdown-чанки получают `page_number: 0` — у них нет страницы оригинала.

## Карта пайплайна

```text
PDF + Markdown
 → [1. Извлечение текста]
 → [2. Чанки + метаданные]
 → [3. Embeddings]
 → [4. Векторная база]
 → [5. Поиск top_k + кэш]
 → [6. LLM-ответ + источники]
```

1. **Извлечение текста** — `ingest.py` читает PDF (PyMuPDF) и Markdown-файлы из `data/source/`.
2. **Чанки + метаданные** — нарезание текста, номер страницы, флаг `has_figure`.
3. **Embeddings** — локальные эмбеддинги ChromaDB (`all-MiniLM-L6-v2`).
4. **Векторная база** — ChromaDB, коллекция `phonetics_chunks`, каталог `chroma_db/`.
5. **Поиск top_k + кэш** — retrieval по фонеме; перед retrieval/LLM — SQLite-кэш.
6. **LLM-ответ + источники** — OpenAI для абзаца артикуляции; страницы источников собирает Python.

## Назначение файлов

| Файл | Роль |
|------|------|
| `ingest.py` | PDF и Markdown → чанки и метаданные → `data/processed/chunks.json` |
| `vector_store.py` | Индексация чанков в ChromaDB |
| `rag_pipeline.py` | Парсинг ввода/IPA, сортировка фонем, retrieval, кэш, LLM, сборка ответа |
| `app.py` | CLI: интерактивный ввод или одноразовый аргумент командной строки |

## Ожидаемое поведение по фонемам

Валидированный набор MVP: **`/p/`**, **`/f/`**, **`/v/`**, **`/z/`**.

| Фонема | Поведение |
|--------|-----------|
| `/f/` | контекст со **стр. 44** |
| `/v/` | контекст со **стр. 44 и 79** |
| `/p/` | контекст со **стр. 36** |
| `/z/` | контекст со **стр. 47** |
| `/aɪ/`, `/θ/`, `/ɔː/`, `/t/` и прочие вне набора | честный отказ шаблоном MVP (без выдуманного описания) |

Для `five | /faɪv/`: сначала согласные по месту образования (`/f/`, `/v/`), затем гласная `/aɪ/` с отказом.

## SQLite-кэш

- Файл: `data/cache.sqlite3`
- Ключ: нормализованная строка `word.lower()|ipa.strip()` (функция `normalize_cache_key`)
- При попадании печатается `cache hit -> ...`
- При промахе — `cache miss -> ...`, затем retrieval/LLM и запись в кэш
- Ошибка формата IPA **не** создаёт запись и **не** печатает hit/miss

## Источники и рисунки

- Строку **«Источники: стр. …»** формирует **Python**, не LLM.
- Если у использованного чанка `has_figure=True`, Python добавляет строку вида **`см. рис. на стр. N`**.
- Изображения **не парсятся** и **не описываются** (нет VLM): только текстовая отсылка к странице.

## Ограничения

Валидированы только фонемы **`/p/`**, **`/f/`**, **`/v/`**, **`/z/`**.

В MVP **не входят**:

- VLM и описание изображений;
- мультимодальный поиск;
- web- или Telegram-интерфейс;
- Docker;
- несколько PDF или несколько LLM;
- оценка качества RAGAS.

OCR учебника может искажать IPA в тексте PDF; поэтому retrieval ограничен валидированными страницами для поддерживаемых фонем.

## Время ответа (факт)

Требование задания — время ответа менее 30 секунд. Замерено на слове `five | /faɪv/`, которое содержит два валидированных звука (`/f/` и `/v/`), то есть требует двух отдельных обращений к OpenAI API.

| Сценарий | Время | Комментарий |
|----------|-------|-------------|
| Холодный запрос (без кэша, `cache miss`) | **13.99 сек** | включает 2 вызова OpenAI API — для `/f/` и `/v/` отдельно |
| Повторный запрос (тот же ввод, `cache hit`) | **2.18 сек** | ускорение ≈ 6.4× относительно холодного запроса |

Требование «менее 30 секунд» выполнено с запасом — холодный запрос почти в 2 раза быстрее лимита.

Уточнение по методике: перед замером холодного запроса запись `five|/faɪv/` была удалена из `data/cache.sqlite3`, иначе оба запуска дали бы `cache hit`. Большая часть кэшированных 2.18 сек — это старт самого процесса Python и импорт библиотек (ChromaDB и другие), а не поиск в SQLite; внутри уже запущенного процесса (например, в интерактивном режиме `python app.py` без выхода) повторный ответ был бы заметно быстрее.
